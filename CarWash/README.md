В первой работе описаны клиенты, автомобили, услуги и заказы. Во второй добавлен REST API для работы с этими данными и пять отчётов. При запуске сервер загружает по 10 записей каждого вида. Изменения хранятся в памяти до остановки сервера.

## Как запустить

Нужен стабильный .NET SDK 10. Из корня репозитория выполни:

```sh
dotnet run --project CarWash/CarWash.Api
```

В Visual Studio открой `CarWash.slnx` и выбери `CarWash.Api` как запускаемый проект. Профиль разработки использует порт 5081. Страница [Scalar](http://localhost:5081/scalar) позволяет отправлять запросы. [Описание OpenAPI](http://localhost:5081/openapi/v1.json) доступно в том же режиме.

## CRUD

Коллекции доступны по адресам `/api/clients`, `/api/vehicles`, `/api/services` и `/api/orders`.

| Запрос | Результат |
|---|---|
| `GET /api/services` | Список услуг → 200 |
| `GET /api/services/{id}` | Услуга → 200, неизвестный ID → 404 |
| `POST /api/services` | Новая услуга → 201 и адрес записи в `Location` |
| `PUT /api/services/{id}` | Обновлённая услуга → 200, неизвестный ID → 404 |
| `DELETE /api/services/{id}` | Удаление → 204, неизвестный ID → 404 |

Сервер сам выдаёт ID. Неверные данные дают `400`. Конфликт расписания, повторный госномер или удаление записи, на которую ссылаются другие записи, дают `409`. Чтобы сохранить связи и расписание, сервер отклоняет смену владельца или категории автомобиля с заказами и смену категории или длительности услуги с заказами.

Пример создания услуги:

```json
{
  "name": "Мойка стёкол",
  "price": 450,
  "durationMinutes": 15,
  "category": 1
}
```

Категории: `1` — легковой автомобиль, `2` — грузовик, `3` — мотоцикл. Время начала заказа передаётся с часовым смещением, например `2026-09-14T10:00:00+04:00`.

## Аналитика

| GET-запрос | Результат |
|---|---|
| `/api/analytics/top-clients` | Пять клиентов по числу заказов |
| `/api/analytics/top-services` | Пять услуг по числу заказов |
| `/api/analytics/vehicles-in-wash` | Машины на мойке. Параметр `at` задаёт время, по умолчанию берётся текущее |
| `/api/analytics/boxes/1/availability` | Время окончания всех записей в боксе, включая будущие. У бокса без записей `freeFrom` равен `null` |
| `/api/analytics/service-revenue` | Выручка по каждой услуге по её текущей цене. Для услуг без заказов — ноль |

Каждый заказ считается одним посещением клиента. При равном числе заказов отчёты сортируются по имени клиента или названию услуги.

Заказы в начальных данных привязаны к 14 сентября 2026 года. Чтобы увидеть машины на мойке в тестовом расписании, передай `at=2026-09-14T10%3A00%3A00%2B04%3A00`. На точной границе окончания машина уже не входит в результат. Для бокса № 1 время окончания — 11:30 по Саратову.

## Структура и проверка

- `CarWash.Domain` — модель и интерфейс репозитория.
- `CarWash.Infrastructure.InMemory` — хранение и начальные данные.
- `CarWash.Contracts` — входные данные, ответы и интерфейсы сервисов.
- `CarWash.Application` — операции над сущностями и отчёты.
- `CarWash.Api` — контроллеры и настройка приложения.
- `CarWash.Tests` — пять тестов аналитики и три проверки HTTP API на xUnit v3.

Из корня репозитория:

```sh
dotnet test --solution CarWash/CarWash.slnx
```

GitHub Actions собирает решение и запускает тесты при отправке в `lab2` и при обновлении PR в `main`.
